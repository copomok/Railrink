# 홈 동적 인사말

홈의 기존 `home-greeting` 영역에 제목과 부제목을 표시한다. 로고·브랜드·상단 여백·검색 카드·메뉴·반응형 규칙은 변경하지 않았다. 기존 h1 타이포그래피를 그대로 사용하고 두 문구를 각각 block span으로 표시해 긴 문구만 자연스럽게 줄바꿈한다. 애니메이션이나 반복 추첨에 따른 높이 변경은 없다.

## 문구 관리

`js/greeting-data.js`에 요청된 문구 **001~110을 원문 그대로** 등록했다. 각 항목에는 숫자 ID, 제목, 부제목, 분류, 적용 조건이 있다. 총 **23개 category, 24개 조건 그룹**이다. 연휴 093~094와 기타 공휴일 099~100은 모두 `holiday` category이며 적용 조건은 각각 `period`와 `other`다.

| 분류 | ID | 개수 |
| --- | --- | --- |
| 일반 새벽·아침·오전·오후·저녁·밤 | 001~036 | 각 6개, 36개 |
| 월·화~목·금·토·일 | 037~056 | 각 4개, 20개 |
| 월초·월말 | 057~064 | 각 4개, 8개 |
| 봄·여름·가을·겨울 | 065~088 | 각 6개, 24개 |
| 새해·설·연휴·추석·연말·기타 공휴일 | 089~100 | 각 2개, 12개 |
| 심야 전용 | 101~110 | 10개 |

## 날짜 및 추첨

기존 `railway-time.js`의 `dateAt`, `clockAt`, `minuteOf`를 재사용한다. 기기 시간대와 관계없이 Asia/Seoul 기준 연월일과 분을 구하고, 해당 한국 날짜의 요일과 월 일수를 UTC 달력 연산으로 얻는다. 월말은 `마지막 날 - 4`일부터이며 윤년 2월도 같은 규칙을 쓴다.

01:30~04:50(04:50:59 포함)에는 공휴일 조회를 포함한 나머지 후보 구성 경로를 실행하지 않고 101~110만 사용한다. 나머지는 시간대 6개 문구에 현재 요일·월초/월말·계절·특별 기간·확인된 공휴일 조건을 합친다. 후보는 동일 확률로 추첨하며 별도의 가중치는 없다.

`createGreetingSession()`은 한 문서 실행당 한 번 만들어진다. 한국 날짜와 시간대의 조합을 키로 삼아 추첨 결과를 메모리에 유지한다. 일반 렌더링, 검색 입력, 탭 전환, SPA 화면 이동에는 추첨하지 않는다. 전체 새로고침 또는 새 문서로 앱을 시작하면 새 세션이 만들어진다. 단순 백그라운드 복귀와 브라우저 BFCache 복귀는 같은 문서 세션으로 취급한다.

직전 ID만 `raillink.greeting.last`에 저장한다. 기존 화면 설정·최근 검색과 같은 가벼운 localStorage 설정이며, 예약용 IndexedDB는 변경하지 않는다. 다음 추첨에서는 가능한 한 직전 ID를 제외한다. 저장 권한 거절이나 용량 부족은 홈 화면을 중단시키지 않는다. 이 경우 실행 중 유지 기능은 동작하지만 새로고침 간 중복 방지는 보장할 수 없다.

홈을 보고 있을 때 기존 분 경계 타이머, `visibilitychange`, `pageshow`에서 변경 필요 여부만 확인한다. 날짜/시간대가 바뀌었을 때만 두 텍스트 노드를 갱신한다. 검색 입력과 열린 역 검색창·입력 포커스·스크롤은 교체하지 않는다. 다른 화면에서는 추첨하지 않으며 홈에 돌아올 때 현재 시간대를 확인한다.

## 공휴일 데이터의 범위와 추가 절차

원본 `NIMBYRAILTABLE/js/features/nimbi_delay.js::_simIsKoreanHoliday`에 있는 양력 고정일 8개(1/1, 3/1, 5/5, 6/6, 8/15, 10/3, 10/9, 12/25)를 인사말용 달력에 반영했다. 원본의 중국 음력 `Intl` 추정 및 기기 로컬 시간 연산은 사용하지 않는다. 새해 1/1~1/3 및 연말 12/24~12/31은 공휴일 여부와 별개인 명시적 특별 기간이다.

설날·추석·대체공휴일·임시공휴일·연휴 확장일은 `js/greeting-holidays.js`의 `VERIFIED_GREETING_HOLIDAYS`에 검증된 양력 날짜를 등록하는 구조다. 임의의 음력 계산, 연도별 명절 날짜 하드코딩, 주말/징검다리를 임의로 연휴로 판단하는 로직은 없다.

등록 필드:

- `date`: 확인한 양력 날짜 `YYYY-MM-DD`.
- `name`: 해당 휴일 이름.
- `kind`: `lunarNewYear`, `chuseok`, `other` 중 하나.
- `period`: 확인된 연휴 기간의 날인지 여부. 설·추석 날짜는 연휴 조건도 충족한다.
- `source`: 확인한 공식 자료 URL.
- `verifiedOn`: 자료를 검토한 날짜 `YYYY-MM-DD`.
- `verified`: 검토 완료 시에만 `true`.

검증 표시·출처·검토일이 없거나 유효하지 않은 날짜는 후보군에 사용하지 않는다. 검증된 날짜만 하루 단위로 등록하며 인접 날짜로 확대하지 않는다.

이번 환경에서 한국천문연구원 공식 달력 페이지(`https://astro.kasi.re.kr/life/pageView/5`) 접근이 HTTP 403으로 차단되었고, 원본에 검증된 연도별 명절 날짜표는 없었다. 따라서 등록표는 비워 두었다. **설·추석 문구 자체는 등록되어 있지만, 공식 날짜 확인 및 등록 전에는 실제 홈에 노출되지 않는다.** 기타 고정일 외의 공휴일도 추측하여 표시하지 않는다.

## 변경 파일

- `js/greeting-data.js`: 110개 문구와 조건.
- `js/greeting-holidays.js`: 확인된 고정 공휴일 및 검증 날짜 등록 구조.
- `js/greetings.js`: 한국 날짜 문맥, 후보 추출, 중복 방지, 세션, 텍스트 갱신.
- `js/home.js`: 기존 영역에 제목/부제목 렌더링.
- `js/app.js`: 앱 실행 세션 연결 및 기존 타이머·복귀 이벤트 연동.
- `css/home.css`: 기존 글꼴·여백을 유지하는 줄바꿈 규칙.
- `tests/greetings.test.mjs`: 8개 단위 테스트 사례.
- `tools/verify-greetings.py`: 실제 브라우저의 세션·경계·포커스·반응형 검사.
- `tools/verify-home.py`: 이전 관광상품 카드 수정에 맞춰 오래된 테스트 선택자만 갱신.

## 검증

```sh
npm run check
npm test
npm run build
python tools/verify-greetings.py
python tools/verify-home.py
```

단위 테스트는 시간 주입으로 모든 요청 경계(01:29/01:30/04:50/04:51 포함), 7요일, 월초·월말, 윤년, 계절, 연말/새해, 공휴일 등록 계약, 새 실행 세션, 반복 렌더링, 중복 제외, 저장 불가 상황을 확인한다. 설·추석 등록 계약 테스트에는 실제 휴일이라고 주장하지 않는 합성 날짜표를 사용한다. 실제 명절 날짜의 검증은 자료 등록 후 별도 필요하다.

브라우저 검증은 LA 기기 시간대에서도 한국 시간 경계가 적용되는지, 새로고침 시 직전 문구 제외, 내부 이동 및 일반 갱신 시 동일 문구 유지, 분 경계 및 복귀 갱신, 역 검색창 포커스 보존을 확인한다. 110개 문구를 라이트/다크 및 320/390/768/1280px 폭에서 검사하고 기존 홈에서 검색→좌석 선택→발매 흐름도 검증한다. 스크린샷은 `artifacts/greetings/`(Git 제외)에 저장한다.
