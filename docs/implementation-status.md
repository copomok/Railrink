# 제품 사양 반영 현황

사용자 제공 「NIMBY Rail Booking & Journey」 사양서와 홈 시안 기준. NIMBY Rail 운행 데이터를 사용하며 서비스 UI는 정식 승차권 발매 흐름으로 제공한다. 결제는 가상 결제다.

## 이번 작업에서 구현한 범위

### 시간·공통 데이터
- `js/railway-time.js`: 한국 시간 날짜, 누적 운행 분, 자정 넘김(역 정차 중 자정 포함), 표시 시각, 역 ID.
- `tools/source.mjs`의 단일 `railDataSource()` 어댑터를 로컬 서버와 정적 빌드가 함께 사용한다. 데이터 사본은 생성하지 않는다.
- 원본에 `sourceId`가 있는 역은 해당 ID를 사용한다. 없는 역은 원본에서 동명이역 정규화를 마친 이름을 식별자로 사용한다. 영문명이나 공식 역 코드를 임의 생성하지 않는다.
- 새 승차권에 열차 ID·역 ID·서비스 날짜·누적 분·도착 절대 시각 저장. 기존 v1 저장 기록도 계속 읽는다.

### 조회·예매
- 당일 **승차역 출발 시각이 현재 시각 이하인 열차는 검색 결과에서 제외**. 내일 열차에는 오늘 시각 필터를 적용하지 않는다.
- 검색 화면을 열어 둔 상태에서도 분 경계에 출발한 행을 제거한다. 좌석 선택 및 최종 저장 직전에도 출발 여부를 다시 검사한다.
- 직통 및 1회 환승. 최소 3분/최대 60분/최대 20건 기본값, 사용자 변경. 선행 도착·후행 출발, 다음날 연결, 대기·총 운임 표시.
- 왕복: 가는 편 좌석을 보관하고 오는 편을 선택한 후 **전체 여정 일괄 저장**. 오는 편은 가는 편 도착 이후로 조회한다.
- `js/inventory-queue.js`: 화면에 보이는 결과부터 한 작업에 한 행씩 모형 재고 계산. 새 검색/화면 이동 시 이전 큐 폐기. 조회 중·여유·보통·혼잡·매진·판매 전·오류 표시.
- 열차 선택 시 예매 시트를 열고 **좌석 선택 / 바로 예매** 중 선택한다. 바로 예매는 실제 남은 좌석에서 무작위로 배정해 승객 정보로 이동한다. 일행은 같은 줄을 우선하며 분리될 때는 별도 확인한다. 직접 선택은 원본 편성·결번·좌석 번호·순/역방향을 유지하고 호차 카드와 고정 하단 예매 버튼으로 표시한다. 인접/창측/복도측/순방향/역방향 자동 선택도 유지한다.
- 승객별 할인, 원본 입석·자유석 판매 조건, 구간별 좌석·입석 혼합 여정과 구간별 운임·좌석 선택.
- 모든 구간 검증 후 IndexedDB 트랜잭션으로 한 번 저장. 실패·시간 겹침·저장 공간 오류 시 일부 승차권만 남기지 않는다.

### 승차권·탑승
- 환승·왕복·혼합 여정 그룹, 아코디언, 날짜/월 달력, 이용 가능·구입 이력 탭과 완료·취소 필터, CSV 내보내기.
- 각 구간의 시간표·당일 운행 정보·QR. 첫 구간 출발 전 전체 취소, 완료·취소 기록 삭제. 그룹 부분 변경은 제공하지 않는다.
- `js/ticket-qr.js`: 표준 QR v3-L byte mode. **로컬 예매 ID만 인코딩**, 개인정보 없음. 원본의 의사 무작위 QR 그림은 복사하지 않았다.
- 홈은 진행 중 여정을 우선 표시하고, 예약/취소/자정 경계 상태를 유지한다.
- `js/operations.js`: 원본 운행 정보 시트와 같은 등급색 헤더·요약·시간표/지도 탭·승하차 구간 강조·승강장·도착/출발 열. `operationStyleSource()`로 원본 운행 시트 CSS를 공유한다. 전체 열차 운행을 기준으로 다음 역과 ETA, 시간표의 열차 아이콘, 등록된 역·통과 지점 좌표의 지도 위치를 표시한다. 승차 전/하차 후에도 열차가 운행 중이면 위치를 표시하며, 운행일이 지난 열차는 다음날 다시 시작하지 않는다.
- 공통 지연 모형 선택 사용, 예정 시각과 모형 지연 예상 시각 병기. 도착·출발 지연을 따로 적용한다. 상태는 분 경계, 위치는 초 단위로 갱신하며 시트·탭·시간표 스크롤·지도 DOM·입력 포커스를 유지한다. 실제 GPS/관제 피드는 아니다.

### 확장·UI
- 정기 일정: 일정명·구간·선호 열차·등급·인원·복수 요일 등록, 4주 미리보기, 기존 일정 충돌/매진/인접 좌석 부족 제외, 가능한 건 일괄 예약. 정기 일정과 발행 승차권은 별도 저장하며 개별 승차권 취소 가능. 실제 정기권 권한은 생성하지 않는다.
- 날짜별 내 여행 시간축, 승차권/승강장/QR 연결. 관광열차는 공통 시간표 사용.
- 앱 열린 동안 출발·도착 준비 안내, 사용자가 버튼으로 허용한 경우 시스템 알림. 자동 대기 배정·백그라운드 알림을 가장하지 않는다.
- 최근 역·즐겨찾기·주요역·초성 분류, 초성·IME·방향키·Enter, 원본 sourceId 검색. 역 검색창은 상단 고정 높이로 결과 수와 무관하게 유지한다. VisualViewport의 키보드 영역 변화를 반영하고 목록만 스크롤한다. 홈 미선택 안내는 출발/도착 모두 ‘선택’이다. 홈 탭과 출도착역 카드 사이 상하 여백을 확보한다.
- 모바일 홈 시안 유지, 태블릿 폭 대응, 데스크톱 230px 사이드바, 라이트/다크/시스템 테마, 등급색 유지.
- manifest·독립 서비스워커. 온라인에서 필요한 파일을 캐시한 뒤 저장 승차권/QR 오프라인 조회. 새 조회·예약·운행 정보는 오프라인에서 차단. 원본 앱 캐시는 삭제하지 않는다.

## 공유 원본과 연결

원본 저장소 `NIMBYRAILTABLE/index.html`의 로드 순서를 따른다. `data/`(운행·역·승강장·동명이역·패치), `js/core/`, `js/shared/nimbi_rail_domain.js`(등급색·요금·편성·시설), 수요·재고·지연 모듈을 직접 읽는다. 로컬은 `/shared/runtime.js`, 독립 Pages는 `/NIMBYRAILTABLE/` 파일을 로드한다. 정적 빌드에 철도 데이터 사본은 없다. 원본 NIMBY Rail 파일은 이번 작업에서 변경하지 않았다.

원본 환승/혼합/예약 함수는 큰 UI 파일의 전역 상태·DOM·로컬 시간 비교와 결합돼 있다. 이를 통째로 복사하지 않고 RailLink 모델과 라우팅 계층에서 같은 원본 시간표·요금·재고를 조합한다. 좌석 판매 규칙과 시설 사실은 새로 정의하지 않았다.

## 남은 세부 사양과 한계

- 역 영문명·공식 역 코드, 실내 길찾기·출입문 방향·좌석별 창문/콘센트의 완전한 메타데이터는 현재 어댑터 범위에 없다. 원본 sourceId를 공식 역 코드로 표기하지 않는다.
- 콘센트·앞뒤·마주보기 선호, 사용자 정의 여행 보드 이름/숙박 구간 편집, 전광판 순환 UI, 지연 환불 대상 계산·환승 위험/좌석 발생 자동 알림은 미구현이다.
- 지도는 원본 역·통과 지점 좌표를 이은 개략도다. 원본 배선 지오데이터 전체를 연결한 실제 선로 선형은 아직 아니다.
- 원본 지연 엔진의 Date 연산은 기기 시간대에 의존하므로 한국 시간대 기기에서만 지연 모형을 적용한다. 그 외 기기는 한국 시간으로 계산한 시간표 상태를 제공한다. 확정 실적 보관/회차 연쇄의 원본 앱과 동일성 전체 검증은 남아 있다.
- 반복 예매는 원본 단일 열차를 선택하는 방식이며 왕복 반복/조건 불충족 날짜 자동 대체 열차는 미지원이다. 여러 날짜를 독립 승차권으로 발행한다.
- 실제 결제·발권·검표 서버·판매 재고·계정 동기화·실시간 철도 장애 피드는 없다. 원본 시뮬레이션으로 한정한다.
- PNG 일반/마스커블/iOS 아이콘을 제공한다. 실제 Android/iOS 설치 검증은 별도 필요하다. 오프라인은 온라인 최초 로드/캐시 완료 이후에만 가능하다.

## 검사와 재현

```sh
npm run check
npm test
npm run build
python tools/verify-home.py
python tools/verify-journey.py
python tools/verify-ticketing.py
```

브라우저 검증에는 Python Playwright와 Chromium이 필요하다. 앱 실행에는 새 npm 의존성이 없다.

자동 테스트 32개 사례: 기존 원본 연결/재고/좌석/변경/취소, 당일 출발 경계/내일, 원자적 일괄 저장과 실패, 승객별 할인, 자정 환승·정차, 통과점 보간, 혼합권 날짜, QR 표준 참조 행렬, 여정 상태/초성 검색, 무작위 배정의 가용 좌석/분리/부족, 승차 전·하차 후 전체 열차 위치, 자정 경계와 도착/출발 지연 차이.

브라우저: 홈 전체 흐름, 출발 행 자동 제거, 단일·왕복·환승 예약, 양쪽 시간표, 자동 배정·할인·전체 취소, 달력·QR, 지연 모형을 켠 운행 지도 및 탭 유지, 반복 예매, 오프라인 재접속, 모바일/태블릿/데스크톱·다크 화면. QR은 테스트 환경에서 Python qrcode 8.2의 표준 행렬과 대조했으며 해당 패키지는 앱 의존성에 추가하지 않았다.

추가 브라우저 검증: 홈 안내/간격, 결과가 적거나 없는 역 검색창 및 축소 뷰포트, 직접·빠른 예매, 호차 전환 후 선택 유지, 입석 버튼 간격, 실제 원본 1574열차의 승차 전 위치/승강장/스크롤/지도 유지. 가상 키보드는 축소 뷰포트로 검증했으며 실제 Android/iOS IME 확인은 별도 필요하다.

스크린샷: `artifacts/home-renewal/`, `artifacts/journey-spec/`, `artifacts/booking-refinements/` (Git 제외). 외부 Pages 배포 성공 여부는 환경의 GitHub API 접근 제한으로 별도 확인해야 한다.

## 최신 UI 및 예약 정책

- 조회 결과의 세 버튼은 단일 조회옵션 창의 열차 종류·환승 여부·조건 변경 탭을 연다. 홈에는 직통/환승 선택을 두지 않는다. 조건을 적용할 때만 재조회하며 취소 시 기존 값과 결과를 유지한다. 결과창을 닫지 않고 역·날짜·시각·인원·등급·정렬·환승 대기를 수정한다.
- `js/search-view.js`, `js/query-options.js`, `css/ticketing.css`: 카드형 조회 결과, 환승 경로 상세, 탭형 조건 변경, 키보드 높이에 반응하는 스크롤 영역과 고정 적용 버튼.
- 좌석 등급 시트의 단일 입석·자유석 항목에서 입석+좌석까지 함께 조회. 혼합권은 원본 재고에서 가능한 구간을 나누고 좌석/입석별 요금을 합산한다. 선택 가능한 혼합 구간이 없으면 예매를 막는다.
- KTX 고정 좌석은 기존 공유 `revRows` 경계의 방향을 보정한다. 일반 KTX는 1~8열 순방향, 9~15열 역방향, 목포 편성은 1~4열 순방향, 이후 역방향이다. 회전식 좌석 편성은 유지한다. 배치도·자동 배정·승차권 표시 모두 `model.seats()` 판정을 사용한다.
- 익명 승객별 할인만 수집하고 새 발매 데이터에는 이름 필드를 저장하지 않는다. 예전 승차권 저장 자료는 유지한다. 가상 결제 영수증은 운임과 실제 청구액 0원을 구분한다.
- 모든 기존 유효 승차권과 신규 여정의 시간 겹침을 저장 직전에 검사한다. 취소권은 제외하며 변경은 교체 대상만 제외한다. 이는 동일 브라우저 저장소 범위이며 서버 계정 또는 기기 간 잠금은 아니다.
- 이용 전 승차권 날짜·매수 띠는 등급색, 이용 완료·취소권은 회색이다. 차내 시설은 시설 항목만, 운행 정보는 기존 원본 시간표·위치 시트를 사용한다.
- `js/pwa.js`: 설치 이벤트·iOS 안내·앱 설치 버튼, 명시적으로 적용하는 업데이트 안내, 오프라인 안내. manifest에는 PNG 192/512 및 maskable 아이콘과 바로가기를 포함하고 iOS 터치 아이콘을 별도 제공한다.
- `tools/verify-ticketing.py`: 조건 탭 전환·취소·적용, 네 열차 분류, 시설/운행 분리, 등급 선택, 가명 없는 발매, 중복 방지, 승차권 색/영수증/이력, 환승 경로·발매, PWA 자산·설치 안내·오프라인, 다크·반응형을 검증한다. 기존 verify-refinements.py는 이 검증을 호출한다. 스크린샷은 `artifacts/ticketing/`에 저장한다.

### 추가 보완
- `js/booking-storage.js`는 기존 v1 저장 값을 읽고 IndexedDB에 여정 전체를 저장한다. 트랜잭션 완료 전에 메모리 상태나 완료 화면을 변경하지 않는다. localStorage는 공간이 있을 때만 호환 사본을 저장한다. 다른 앱의 저장값을 삭제하지 않는다. 저장 실패 원인도 직렬화/권한/용량으로 구분한다.
- 모델은 동기 저장 어댑터와 비동기 저장 어댑터 모두 지원한다. UI에서는 예약·환불·삭제·즐겨찾기 저장을 기다린다. Web Locks와 저장 직전 refresh로 예약 탭의 최신 상태를 읽고 BroadcastChannel로 변경을 알린다.
- 조회옵션은 텍스트 왼쪽·선택 표시 오른쪽의 최소 48px 행으로 표시한다. 이용 가능한 승차권 목록 상단에도 등급색을 적용한다. 혼합 여정은 아직 이용할 구간의 등급색을 사용한다.
- `js/tourism.js`는 관광열차를 대표 편으로 축약하지 않고 종류·노선/기종점 계통·원본 상하행으로 묶어 전체 열차를 시각 순서로 표시한다. 홈 관광상품과 여행 화면이 공유한다.
- 저장 용량 포화 환경은 `tools/verify-storage.py`, 관광열차 수/방향과 선택 표시 배치는 `tools/verify-ticketing.py`로 검증한다. 실제 기기의 설치 PWA 환경은 별도 확인이 필요하다.

### 관광상품 탐색 재구성
- 홈 관광상품과 여행 탭: 남도해양·국악와인 종류 카드만 표시한다. 종류 선택은 별도의 계통 카드 화면(`#tour-routes`)으로 이동한다.
- 계통 선택: 기존 예매 탭(`#results`)에서 그 계통의 관광열차만 조회한다. 하행·상행 전환, 날짜 이동, 정렬, 좌석 선택·바로 예매를 기존 예약 흐름으로 연결한다. 해당 계통은 처음부터 전 목록을 표시하되 이미 출발한 열차는 제외한다.
- 새로운 일반 조회/조건 변경 시 관광 계통 제한을 해제한다. 계통 변경과 뒤로가기는 계통 선택 화면으로 돌아간다.
- `css/tourism.css`와 `js/styles.js`: 관광상품 전용 카드 스타일 및 렌더링 전 스타일 확인. `tools/build-pages.mjs`는 자체 CSS/JS/import/서비스워커에 공통 콘텐츠 버전을 넣는다. 원본 운행 데이터는 기존처럼 직접 읽는다.
- `tools/verify-style-release.py`는 관광 CSS 링크가 누락된 이전 HTML을 재현하여 새 모듈의 스타일 복구·라이트/다크·모바일 폭을 확인한다. `tools/verify-ticketing.py`는 남도해양 → 목포–고현 → 예매 탭의 하행 7편/상행 7편과 홈 관광상품 진입을 확인한다.
