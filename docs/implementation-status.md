# 제품 사양 반영 현황

2026-10-29. 사용자 제공 제품 사양서 및 최신 홈 시안(1000079413.jpg) 기준.

## 이번 구현

- 홈: 인사말, 연한 산 능선 배경, 예약 종류 탭, 가로 출도착역·교환, 날짜/출발 시각, 인원/등급, 조회 버튼, 네 개 바로가기, 관광 배너, 저장된 일정. 날짜·열차·좌석·요금은 시안에서 가져오지 않는다.
- 홈/예매/승차권/여행/더보기의 다섯 내비게이션. 기존 `#search` 링크와 예매 흐름 유지.
- 정기권 탭은 판매 불가 안내와 실제 저장 구간 조회/관리, 관광상품 탭은 원본 시간표 관광열차 조회. 상품 가격·권한을 임의로 만들지 않는다.
- `js/home.js`: 홈 표현. `js/journey.js`: 시간표 기반 여정 상태 및 초성 검색. `js/app.js`: 이벤트와 화면 연결. 공통 철도 규칙은 원본 저장소에 유지.
- 이용 예정/출발 10분 전 승차 준비/탑승 중/도착 5분 전 준비/완료. 자정 이후 도착 계산, 진행 중 여정 우선순위, 취소·변경 제외. 기존 승차권 목록의 출발 즉시 지난 일정 분류 오류 수정.
- 분 경계에서 홈 일정 영역만 갱신하며 입력창·열린 시트는 유지. 실제 위치/지연 반영을 의미하지 않으며 시간표 기준이라고 표시한다.
- 역 검색의 초성·IME 조합·방향키·Enter, combobox/listbox 관계, 탭의 방향키/Home/End. 원본 역명 목록을 그대로 사용.
- 출발 기준 시각 입력과 실제 검색 필터 연결.

## 기존 기능과 공유 원본

직통 조회, 필터·정렬, 편성 기반 좌석 선택, 승객 별칭/할인, 로컬 시제품 예약, 단일 예약 변경/취소, 좌석 대기 기록, 시설·정차역 안내를 유지한다.

`tools/source.mjs` 및 `tools/build-pages.mjs`가 NIMBYRAILTABLE의 index.html 스크립트 순서와 `js/shared/nimbi_rail_domain.js`, data/, core/, 재고·수요·지연 모듈을 읽는다. 홈은 같은 model.byKey와 model.read()를 사용한다. 원본 철도 DB 복제나 원본 앱 코드 변경은 이번 작업에 없다.

## 아직 남은 사양

아래는 이번 홈 개편에서 완료한 것으로 간주하지 않는다.

- 역 ID/영문/코드/동명이역 메타데이터 어댑터, 즐겨찾는 역. 현재 문자열 역명 검색의 한계가 남아 있다.
- 환승 검색·환승권, 왕복 원자적 일괄 저장. 기존 왕복은 편도별 별도 확정이다.
- 입석·자유석·구간 혼합권, 자동 배정, 승객별 할인.
- 화면에 보이는 결과의 재고만 지연 계산하는 큐. 기존 결과 재고 계산을 유지한다.
- 실시간 모형 지연을 반영하는 여정/운행 지도, 통과 지점 보간, QR 시제품, 승차권 달력.
- 정기권 반복 예매·여행 보드·시스템 알림, PWA 오프라인 정책.
- 데스크톱 사이드바·태블릿 레이아웃·다크 테마. 현재 넓은 화면은 모바일 앱 중심 폭을 유지한다.

이 중 게임 시뮬레이션 기능은 후속 구현 가능하다. 실제 결제·발권·판매 재고·실시간 철도 피드·실내 길찾기는 현재 백엔드/원천 데이터가 없어 별도 연동이 필요하다.

## 검증

- `npm run check`, `npm test`, `npm run build`.
- 모델 기존 8개 사례 및 여정/초성 검색 3개 사례. 자정 경계, 출발/도착 경계, 취소·변경/과거 제외, 일정 정렬 검증.
- Playwright/Chromium: 독립 `/Railrink/` 배포 경로, 원본 `/NIMBYRAILTABLE/data/` 요청, 홈 탭 키보드 전환, 초성/IME 역 선택, 시각 필터, 조회→좌석→승객→확인→예약 완료→홈 일정, 알림, 운행 중 승차권 확인, 320/390/600/1280px 넘침 검사.
- 수동 화면 확인: `artifacts/home-renewal/`의 홈 스크린샷(로컬 산출물, Git 제외).
- GitHub Pages 외부 배포 성공 여부는 이 환경의 GitHub API/Pages 접근 제한 때문에 별도 확인 필요.
